# Knowledge base — Phase 1

The eight manifest entries use all six required formats. Every source explicitly belongs to the synthetic assessment corpus. The taxonomy is `product`, `policy`, `qualification`, `faq`, `objection`, `support`. Manifest metadata supplies product, category, version, language and synthetic status; source sections supply titles.

Extraction returns `ExtractedUnit(document_id, text, source, page, section, metadata)`. PDF pages are one-based. Explicit Markdown-style headings are separated before chunking. HTML excludes navigation, headers, footers, scripts, styles and sidebars and selects `main`/`article` where possible. JSON accepts object records or a `records` array; CSV maps one row per unit. Blank, corrupt, missing and unsupported sources produce safe failed-source codes in the report.

Cleaning is deterministic: Unicode/whitespace normalization, repeated short edge-line removal, obvious navigation/page-number removal, bullet/heading normalization, day-first common date normalization, and a configurable terminology map. Repeated edge lines are a heuristic; real document review must verify that meaningful lines were retained. The [before/after fixture](../data/fixtures/cleaning.json) and PDF tests verify preservation of fees and page references.

PII redaction runs before hashing, chunk persistence and embedding. It covers emails, common international/parenthesized phone forms, long account/card-like numbers and configurable government-ID regexes. Long account strings are processed before shorter government-ID patterns to prevent partial redaction. Clearly labelled monetary amounts are preserved. `contains_pii` means the source unit contained PII **before redaction**; retrieval holds only the redacted text. It is not evidence that raw PII remains in the vector payload.

Exact dedupe hashes case/whitespace-normalized redacted content, scoped to product/language/version/category. Within a complete ingestion, duplicate units are skipped. Incremental ingestion also compares new chunk hashes with retained records. Near duplicates use token Jaccard similarity and are flagged **and retained**; automatically discarding a nearly identical rule can remove a material numeric change. The report identifies canonical document/section or retained record ID. Full rebuilds establish canonical source precedence from manifest order; incremental exact matches use the retained source as canonical. Similarity detection across separate incremental batches is limited to exact chunks; use a full rebuild to review all near duplicates together.

Chunks remain within a source page/heading. Short sections are not padded to a token target. Long sections use a configurable 400-word maximum, sentence-end preference and 60-word overlap. These are word counts, not tokenizer-measured tokens. Each record includes stable `record_id`, document ID, title, content, category, product, source/type, page/section, version, PII flag, language, redacted-content checksum, creation timestamp and synthetic flag. The [manual review](chunk-review.md) inspected twelve records.

`scripts/ingest.py --rebuild` prepares the new corpus before switching a Qdrant alias; any failed source aborts a complete rebuild. HTTP ingestion accepts **only manifest-registered paths**, preventing arbitrary local file reads. It replaces all indexed versions of successfully ingested document IDs and retains other documents; failed source versions remain intact. A partial run is labelled `partial`. The current complete redacted snapshot and report are written to `data/normalized/records.jsonl` and `ingestion_report.json`, which are ignored by Git.

Index publication and filesystem export are separate operations. If the index was published but snapshot export failed, the report explicitly returns `partial` with `index_published_snapshot_export_failed`; the active index is usable, but the operator must repair disk access and rerun ingestion to refresh the local snapshot.

Search normalizes/redacts the query, embeds it, applies product and language filters, and returns cosine-ranked records with full metadata. Low-scoring hits remain visible for inspection. `grounded` requires the configured evidence threshold. Hash mode also requires 75% meaningful query-token coverage to reject vector hash collisions and mixed unsupported topics. This gate is deliberately conservative; it cannot perform full semantic entailment. For example, the paperwork paraphrase in the actual evaluation safely falls back despite available document requirements.

Answer retrieval happens first. Only eligible records reach the answer adapter. The hosted LLM receives retrieved context and the query, not the whole KB in a system prompt. The provider selects at most two verbatim quotes. The server rejects invented IDs, modified text and empty output, constructs the answer from validated quotes and supplies citations. Unknown questions, empty indexes, provider errors/timeouts and failed quote validation produce an explicit unavailable-information fallback offering a human representative. No escalation action is scheduled in this phase.

The [retrieval report](q2-retrieval-evaluation.md) is generated from actual vector searches and answer calls. It records the known lexical paraphrase miss rather than inventing an accuracy claim. Confidence thresholds need recalibration after any provider/model change. No Q4 latency numbers are claimed in this phase.
